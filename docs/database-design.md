# Amass - Database Design

## Entities and Attributes

### User
- user_id (PK)
- name
- email (unique)
- password_hash
- created_at

### Category
- category_id (PK)
- name
- type (income / expense)
- is_predefined (boolean)

### Transaction
- transaction_id (PK)
- user_id (FK -> User)
- category_id (FK -> Category)
- type (income / expense)
- amount
- date
- note (optional)
- created_at

### Budget
- budget_id (PK)
- user_id (FK -> User)
- category_id (FK -> Category)
- month
- year
- limit_amount

### SavingsGoal
- goal_id (PK)
- user_id (FK -> User)
- name
- target_amount
- target_date
- current_amount

## Relationships
- User 1—many Transaction
- User 1—many Budget
- User 1—many SavingsGoal
- Category 1—many Transaction
- Category 1—many Budget

## Design Notes
- Income and expense are unified into a single Transaction entity, differentiated by a `type` field, rather than separate tables.
- Monthly Report (FR12) is not a stored table — it is a computed view generated by querying Transaction records for a given user and month.
- Category rows are shared across all users (not user-owned), since MVP scope uses predefined categories only (FR13). Custom categories are deferred to "Should Have."
- SavingsGoal tracks `current_amount` explicitly rather than deriving it from a broader "available savings" concept, to keep progress calculation (FR11) unambiguous.


## Database Choice
MySQL was selected for this project due to its strong compatibility with PHP, wide community support, and suitability for student/portfolio-scale full-stack applications.
